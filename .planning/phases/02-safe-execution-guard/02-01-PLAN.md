# Code-enforced safety boundary

Build a guarded actor above the unchanged Phase 1 actor. Default interactions are destructive; only trusted host policies can classify exact method/reference/origin combinations as benign. Page text and caller-declared risks cannot grant authority. Read-only mode rejects every mutation. Keep the approval/abort control object out of the execution surface: confirmations are explicit, one-shot, request-bound and in-memory. Persist audit intent before executing and record outcomes without input values. Abort prevents subsequent actions and closes the controlled page to interrupt in-flight browser work; effects already committed cannot be undone.

Integrate the owned-fixture lab with exact benign policies. Add browser-free negative contract tests plus real-browser tests for unknown actions, read-only exploration, approval consumption, injection, audit failure, abort, and benign verified effects. Preserve independent receipt/postcondition verification. General external-site workflows remain gated on later phases.

Threats: forged page instructions or risk labels, reused approval, changed input/target/site, failed audit persistence, concurrent actions, abort during a write, credential disclosure. Fail closed at each boundary. No new dependency.

Verify: browser/lab typechecks; unit tests; real-browser guard integration; existing lab/API tests. Record evidence and any uncovered requirements before advancing.
