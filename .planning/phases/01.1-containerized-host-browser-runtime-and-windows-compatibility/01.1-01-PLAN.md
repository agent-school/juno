<objective>
Add the explicit attach-only browser transport that lets the Dockerized Juno client connect to a host-owned Windows Chrome while leaving the existing local BrowserSession launch path untouched.

Purpose: D-01, D-03, D-04, D-05, and D-08 require the transport boundary to be proven before Docker and Windows orchestration are layered around it. The endpoint response is a privileged control-plane input, so readiness and websocket normalization must fail closed rather than turning a reachable port into an assumed browser.

Output: A typed CDP readiness module, an attach-only session facade, public exports, and a real semantic attach/read/benign-act tracer plus browser-free negative-path tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Trusted runtime configuration → CDP HTTP probe | The configured host endpoint controls a privileged browser connection; it is not page-derived data. |
| CDP `/json/version/` response → websocket connection | Host service metadata is untrusted until schema, scheme, path, and origin are validated. |
| Attached page → SemanticPageReader/SemanticActor | Page-controlled accessibility content is consumed by the existing validated, fail-safe semantic boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Spoofing/Tampering | cdp-readiness.ts endpoint and websocket resolution | high | mitigate | Require trusted configured endpoint, validate `/json/version/`, require browser websocket scheme/path, and rewrite only the configured host/port before attach; cover mismatches in unit tests. |
| T-01-02 | Elevation of privilege | cdp-session.ts attach boundary | high | mitigate | Expose attach-only lifecycle, reject missing default context, never accept page-provided endpoints or profile paths, and preserve explicit host process ownership for the Windows launcher. |
| T-01-03 | Information Disclosure | adapter errors and logs | medium | mitigate | Report only stage, host/port, and browser/protocol version; never include cookies, page text, or profile contents. |
| T-01-04 | Denial of service | readiness polling | medium | mitigate | Use bounded deadline and interval controls; reject malformed or unavailable endpoints instead of unbounded retries. |
| T-01-SC | Tampering | pnpm/npm dependency installation | high | mitigate | Add no dependency; retain the pinned Phase 1 manifests and verify the existing no-stealth/package policy. |
