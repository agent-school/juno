# Phase 01.1 Context

## Decisions

- **D-01:** Juno runs in Docker and attaches over CDP to a separately and explicitly launched, dedicated Windows Chrome process. The container must never launch Chrome and must never attach to an arbitrary already-running browser.
- **D-02:** The product path does not use noVNC, stealth/evasion tooling, CAPTCHA automation, or the user's daily-driver Chrome profile. The Windows browser uses a separate persistent Juno profile.
- **D-03:** Preserve the existing Linux/local `BrowserSession` launch mode and its public behavior. Add attach mode beneath the existing `SemanticPageReader` and `SemanticActor` without changing their semantic read, reference, fail-safe, or action semantics.
- **D-04:** Use Docker bridge networking with `host.docker.internal` as the default host route. Use a configurable fixed CDP port with preflight and bounded retry; do not switch to host networking as the default.
- **D-05:** Treat Windows compatibility as a first-class requirement: no host Node.js or pnpm requirement; robust Chrome discovery; correct paths containing spaces, apostrophes, trailing separators, or Unicode; dedicated profile and owned-PID tracking; Chrome 136+ non-default-profile handling; bounded local and container `/json/version` readiness polling; websocket endpoint normalization for the Docker host route; and safe Docker Desktop networking/firewall behavior.
- **D-06:** The integration fixture has one clear owner, configurable ports, no stale-server reuse in CDP runs, and cleanup on success, failure, Ctrl-C, attach failure, Docker stop, and container teardown. Cleanup may stop only the Chrome process tree proven to belong to this run; persistent profiles remain intact.
- **D-07:** The phase must include actual Windows smoke-test gates covering discovery, profile safety, path quoting, port ownership, Docker bridge reachability, semantic attach/read/benign-act behavior, and every required cleanup path, with explicit PowerShell scripts and documentation.
- **D-08:** Prefer the smallest implementation that reuses the pinned Phase 1 Playwright 1.62.1 stack and adds no CDP helper, process manager, relay, or other npm dependency.

## Agent Discretion

- Choose exact TypeScript class/function names and error subclasses while keeping the attach API explicit and typed.
- Choose the validated Stable Chrome candidate-path list and the PowerShell argument-quoting technique, subject to the Windows path matrix in D-05 and D-07.
- Choose the exact Docker Compose variable names and the human-supplied Docker/WSL firewall source scope, but fail closed when that scope cannot be established safely.
- Keep the existing local Playwright configuration behavior intact; introduce a separate CDP configuration for the container harness.
