# Phase 01.1 — implementation with Windows gates open

CDP readiness/session, separate no-browser Docker image, bridge Compose fixture harness, strict no-reuse configuration, owned Windows launcher, helper tests and runtime documentation are implemented. Original BrowserSession/reader/actor sources remain unchanged.

Verified on Linux: malformed endpoint/metadata/deadline contracts; real dedicated Chrome attach/read/fill/click/observable list effect; disconnect and failed-navigation survival; image build and two passing container bridge tracer/cleanup tests. The Linux bridge test uses an explicitly owned, bridge-bound diagnostic TCP relay because Linux Chrome binds loopback. This relay is not shipped in the Windows runtime and does not validate Docker Desktop host forwarding. Compose/container/network teardown completed after both failed and passing runs; temporary test profiles are removed with bounded retries after Chrome flushes.

Bridge testing found Chrome rejects DNS aliases in Host headers. Node fetch ignores Host overrides, so the native HTTP(S) readiness client sends a fixed localhost Host header, caps the response and keeps certificate validation. CDP websocket connection uses the same fixed header. Connections still go only to the explicitly configured authority. Real HTTP-header and real container tests cover both boundaries.

PowerShell helper contracts pass on Linux PowerShell 7.4.22 (official release asset SHA-256 verified). A Windows PowerShell CI job is added, but actual Windows/Chrome/Docker Desktop evidence remains required. Discovery, special-path launches, listener ownership, scoped firewall creation and normal/error/Ctrl-C/container-stop cleanup must pass the matrix in docs/windows-cdp-runtime.md before this phase is complete. RUNTIME-01/02/03/04/06 remain open; RUNTIME-05's unchanged semantics and attach equivalence are verified.
