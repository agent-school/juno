<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Windows host ↔ Docker bridge | Host CDP is a privileged service and the published fixture is a browser-reachable test service; each direction needs a narrow route. |
| Compose environment → attach adapter | CDP and fixture origins are runtime configuration and must remain explicit, bounded, and distinct. |
| Container webServer → fixture port | The fixture is a mutable test resource whose ownership must not be confused with a pre-existing listener. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Elevation of privilege | Docker bridge to Windows CDP | high | mitigate | Keep bridge networking, avoid publishing CDP from the container, route through the configured host endpoint, and defer listener/firewall admission to the Windows launcher with a scoped rule. |
| T-02-02 | Spoofing/Tampering | Compose endpoint and fixture ownership | high | mitigate | Pass the endpoint explicitly, use one Compose/webServer owner, disable reuse in CDP config, and reject listen collisions instead of attaching to whatever answers. |
| T-02-03 | Information Disclosure | Docker mounts and test environment | medium | mitigate | Do not mount the Windows profile or cookies into the image; keep only source/dependency artifacts needed for tests and avoid logging sensitive runtime values. |
| T-02-04 | Denial of service | Fixture and container teardown | medium | mitigate | Use `--rm`/Compose teardown, one worker, explicit port checks, and cleanup tests for client close and failure paths. |
| T-02-SC | Tampering | pnpm/npm dependency installation | high | mitigate | Install only the existing lockfile dependencies inside the Docker image; no new CDP, relay, noVNC, or stealth package is introduced. |
</threat_model>
