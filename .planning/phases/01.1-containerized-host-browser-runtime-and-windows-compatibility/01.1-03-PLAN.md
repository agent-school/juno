<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PowerShell parameters/config → Windows process launch | Executable, profile, port, and firewall values control a privileged browser process and must be validated before launch. |
| Windows host CDP listener ↔ Docker bridge | CDP can expose authenticated browser state; the listener must be reachable by Docker but not broadly by the LAN. |
| Docker command/exit → host cleanup | Container success, failure, stop, or interruption determines whether owned Chrome, firewall, and fixture resources must be removed. |
| Browser profile/process identity → cleanup action | A mistaken identity match could kill the user's daily browser or delete the wrong profile. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Elevation of privilege/Information Disclosure | Windows CDP listener and firewall | high | mitigate | Use bridge mode, an explicit scoped Docker/WSL source range, no broad default allow rule, and a fail-closed path when the range is unknown; verify host and container reachability in the smoke gate. |
| T-03-02 | Spoofing/Tampering | Chrome discovery and fixed-port ownership | high | mitigate | Validate explicit/fallback files, preflight and bounded-retry ports, correlate `/json/version` with captured PID/profile/port command-line identity, and reject unrelated listeners. |
| T-03-03 | Information Disclosure/Tampering | profile path and Chrome arguments | high | mitigate | Reject daily-driver roots, require a separate non-default profile for Chrome 136+, quote literal paths safely, never mount the profile into Docker, and avoid logging profile contents or credentials. |
| T-03-04 | Denial of service | Ctrl-C, Docker stop, and failure cleanup | high | mitigate | Use idempotent exit/finally cleanup, targeted process-tree stopping, port-release assertions, Compose teardown, and persistent-profile preservation. |
| T-03-05 | Spoofing | Chrome child-process topology | medium | mitigate | Make ownership correlation and child-tree behavior an actual Windows gate; stop only a process whose command line and profile/port identity match this run. |
| T-03-SC | Tampering | pnpm/npm dependency installation | high | mitigate | Add no new package and run the container from the existing pinned lockfile; keep noVNC, stealth, relays, and process-manager dependencies out of the runtime. |
</threat_model>
