## Acceptance

- Compile once, close the browser, replay new inputs from persisted semantic bindings.
- Reordered DOM succeeds with unchanged contract; renamed control fails without activation; recompilation restores operation explicitly.
- Verify person/note/date/next-action from fixture application state, not successful clicks.
- Repeating the same request ID cannot duplicate a record; fail closed if effects are uncertain.
- Browser clients have isolated data; no arbitrary external URL, CDP, credential or account surface is exposed.
- History and feedback survive a server restart with the same data directory.
- Rolo, Canvas, Windows/CDP, full guard and model-baseline claims remain pending.

## Risks and mitigations

- Hosted browser resource abuse: one browser job globally, bounded lifetime, request-size/rate/data limits, fixture-only navigation and network allowlist.
- Cross-session reads/writes: random HttpOnly SameSite cookie, scoped files, same-origin mutation checks, no client-controlled file paths.
- Guessing during drift: exact unique semantic grounding and no automatic repair/retry after possible write.
- Persistence: atomic files under a mounted volume; single-process lab only. Lab data contains synthetic fixture content, never accounts or credentials.
