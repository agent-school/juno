# Real tasks, durable memory and requested Coolify domain

Initialized with official `gsd-tools.cjs init quick` before edits. This continues PR #2 and does not claim completion of a full roadmap phase.

Jack requested deployment on `juno.agentschool.io` and a real task experience like Muse with strong memory. His Notion Muse task (`3da8a2ee-f320-81ea-8853-f76840831765`) calls for end-to-end workflows, permission boundaries and reliability. Muse's published product description emphasizes task completion, continuity and editable memory. Juno's doctrine separates runtime, episode, application and cross-application memory.

## Slice

- Real read-only operation: research public open-source repositories using GitHub's official API, schema-check each source record and verify its identity and requested filters, produce a sourced shortlist. Prefer the API when available; this is not evidence of semantic browser execution on GitHub.
- Follow-up operation: refresh explicitly remembered projects and show field-level changes from their saved baseline.
- Durable workspace: structured user preferences actually influence execution; editable/versioned notes; user-approved sourced project snapshots; reusable search recipes; task receipts with recalled context, steps, partial failures and timestamps.
- Explicit memory boundary: external descriptions are data, never executable instructions. Search notes are surfaced as context, not interpreted by a hidden planner. No LLM/API key needed for these two operations.
- Passphrase-protected workspace recovery across devices, scrypt credentials separate from shareable memory, owner isolation and bounded records. No automatic merging between accounts.
- Coolify: single instance, `/data` volume, port 5123, HTTPS domain. Access is currently blocked by stored token HTTP 401 and Porkbun parking DNS. Do not claim deployed until HTTPS and persistence are checked.

## Acceptance

1. A real live query returns source-linked, schema-validated public project data with verified requested filters or explicit partial/failure state.
2. Repeating a request ID never executes twice; conflicts reject. Background work continues after the HTTP request and interrupted work is marked honestly on restart.
3. Preferences, notes, source baselines and recipes survive restart. Editing and forgetting work. Refresh compares to the saved baseline without silently overwriting it.
4. Registration/login restore one workspace on another browser; wrong credentials and other owners cannot read it; passwords never appear in exports.
5. UI exposes tasks, evidence, remembered context, and source freshness; retains the controlled browser lab separately.
6. Typecheck/unit/integration checks and real public API smoke pass. Human UI validation requires the testing-agent approval. No unrequested real account writes.

## Constraints

No arbitrary URLs, browser/CDP entry, external write, scheduled monitoring or general autonomous planner. No claim of Muse parity or general website compilation.
